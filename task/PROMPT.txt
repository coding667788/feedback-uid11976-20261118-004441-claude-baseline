实现一个本地身份目录的登录名规则升级工具，解决 Unicode 规范化后产生的账号冲突以及在线迁移的一致性。只管理登录名到不可变 account_id 的映射，凭据始终绑定 account_id；不实现密码验证、第三方登录或真实外部服务。环境为 Windows、Python 3.12 标准库和 SQLite，仅 CPU，不使用 Docker。由你构造虚构账号、样例和测试，不存在额外附件。

一、每个租户独立维护登录名策略和目录 revision。旧策略 V1 使用 NFC(raw_login)，区分大小写；新策略 V2 使用 NFKC(NFKC(raw_login).casefold())。不额外去空白、不做拼音或外观相似字符替换。规范化前后都拒绝空串、任何 isspace() 为真的字符、Unicode 类别 Cc/Cf/Cs，规范化结果 UTF-8 不超过128字节；其他合法字符按上述规则处理。数据库记录创建时使用的 unicodedata.unidata_version，运行库版本不一致时明确拒绝读写，不能默默换规则。账号 ID 不随登录名变化，同租户规范化登录名唯一，不同租户允许重复。

二、升级先生成基于同一目录快照的预检报告，绑定租户、源策略、源目录 revision 和原始账号集合，并计算全部目标登录名。必须完整列出 V2 冲突分组及无效名称，不能自动合并账号或把凭据转到另一账号。操作者可为具体 account_id 提供替代登录名，最终提交计划包含预检依据和完整替代方案；替代方案也按 V2 完整校验，仍有冲突就整版拒绝。允许一批合法方案互换两个账号的登录名，不得被逐行更新的中间唯一性冲突误拒绝。计划的确定性摘要忽略 JSON 对象键顺序、账号及替代方案排列顺序，但保留字符串、类型和 account_id 差异；拒绝重复字段、未知字段及隐式类型转换。等价输入必须生成相同计划内容和摘要。plan_id 在首次提交时绑定计划内容，之后修改方案必须使用新 plan_id，即使前次因业务校验失败也不能换参复用。

提交计划时必须再次核验源 revision 和策略；在计划生成后发生的新增、改名或删除都使计划过期，返回 stale，不得覆盖这些变更。合法提交在一个原子边界内切换策略和全部映射，并且仅增加一次 revision；批量 resolve 在一次调用中只能看到完整旧版或完整新版，不能混用。同一个 plan_id 重试返回原提交结果，不再应用一次；同 plan_id 改替代方案返回 conflict，包括第一次尝试因业务校验失败的情况。提交成功后新开始的查询必须使用该版或更新版，旧登录名不能通过未声明的历史别名继续指向其他账号。

用至少三个独立进程共享同一数据库，固定同步点验证：计划生成与新账号写入交错、两个计划竞争、批量查询与规则切换交错。实际终止自己创建的迁移进程，分别在提交前和提交后但响应未返回时终止；重启、查询并重试，不能出现半迁移或重复增版。用全角与半角、大小写折叠扩展、组合与预组合字符、替代名互换、跨租户同名、非法字符及失败计划换参构造反例。预期冲突分组与账号归属由独立参考逻辑生成，不得用被测迁移输出充当答案。

交付源代码、README、样例及自动化测试，提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口。说明输入输出 schema、错误码、初始化命令及 Windows 运行方式。测试断言具体冲突成员、revision 和最终账号归属，不只打印成功；所有操作只限本题测试目录和自行启动的进程。
